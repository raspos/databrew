마지막 코드 갱신은 GitHub push 시각이며 실제 데이터 공표일과 다릅니다. 작업 상태는 GitHub Actions의 최근 실행 결과일 뿐 서비스 품질이나 지표 정확성에 대한 인증이 아닙니다. 측정 불가 시 숫자를 추정하지 않습니다.

업데이트 지시 · 실행 · 변경

업데이트 요청

프로젝트별 '작업 지시'를 누르면 해당 GitHub 저장소의 이슈 작성 화면이 열립니다. 목적·검증 기준·우선순위를 남기고 변경 결과를 추적하세요. 현재는 이슈 등록만으로 코드가 자동 수정되지는 않습니다.

수집·배포 실행

GitHub Actions를 사용하는 프로젝트는 '워크플로' 링크에서 수동 실행할 수 있습니다. APT워치의 주 운영 수집은 로컬 Windows 작업 스케줄러이며 GitHub Actions는 S3 백업 설정이 필요한 수동 경로입니다.

주기 변경

주기 관리 원장 수정 ↗ · 실제 갱신 시각을 바꾸려면 해당 프로젝트의 cron·Cloudflare·Windows 작업 스케줄러도 함께 변경해야 합니다.

접속자 분석

CRAFT의 기존 카운터는 누적 이벤트 계수이며 순방문자(UV)나 세션과 동등하지 않습니다. 다른 서비스는 분석 도구가 연동되기 전까지 '미측정'으로 표시합니다. 모든 프로젝트에 공통 측정 규격을 적용하는 작업이 필요합니다.

출처: 운영 원장 · 각 GitHub 저장소 · 기존 CRAFT 방문 카운터. 프런트엔드는 접근·수정 권한을 보유하지 않습니다.
